# 问题修复报告（F231）

## 问题描述

闭合 F230（已 ship master `371d728`）在 fix-report「已知限界 0」中如实记录的残留缺口：

fix 依从性门禁的改名跟随（`fix-compliance-core.mjs` 的 `scanRenameCommandEvents` → `resolveFeatureDirCandidate`）在 F230 已从「把 `mv` 当关键字」收紧为「只认**语法命令位**的 `mv`」，但它**只判语法命令位、不判执行可达性**——出现在**不会被执行的控制流分支**里的 `mv` 文本仍被采信为一次真实改名事件，把候选目录跟随到非规范名（`ambiguous=true`），打开 F224 fail-open 降级通道。

Codex 第 5 轮（F230 交付时）已实测确认 6 类绕过构造；本次立项前编排器在当前 master 源码上逐条复现，确认 6 类均触发 fail-open（`{path:null, ambiguous:true}`）：

| 构造 | 命令（`S`=候选目录，`D`=非规范名）| mv 是否真的执行 |
|---|---|---|
| 短路 RHS | `true \|\| mv S D` | 否 |
| 函数定义体（从未调用）| `f() {` 换行 `mv S D` 换行 `}; :` | 否 |
| 死 if 分支 | `if false; then` 换行 `mv S D` 换行 `fi` | 否 |
| 未命中 case 分支 | `case x in y)` 换行 `mv S D` 换行 `;; esac` | 否 |
| 命令替换内 | `: $(false && mv S D)` | 否 |
| 循环体（零次迭代）| `while false; do` 换行 `mv S D` 换行 `done` | 否 |

这 6 类在 HEAD（`371d728`）上逐条同构，**非 F230 引入**。本次立项后经**五轮**审查证明：可触发同一 fail-open 的构造远不止这 6 类，且**判据形态经历两次根本性收敛**（黑名单 → 结构白名单 → 极窄字面白名单），最终形态见「修复策略」。

## 关键设计发现一：为何不用「执行证据」

F230 fix-report 把**执行证据**（核验 Bash `tool_use` 对应的 `tool_result`，F216 `extractExecutionRecordsAfter` 已有 use↔result 配对）写作「唯一可靠修法方向」。**本次立项实测证伪该方向**，两条证据：

1. **`tool_result` 无法区分「被跳过的 mv」与「静默成功的 mv」**。同名 `mv` shim 实跑：6 类构造 mv 均不执行、退出码 0、无输出；`mv S D`（真实静默成功）同样退出码 0、无输出。`mv`/`git mv` 成功时静默无输出；死分支里整条命令退出码由控制流外壳决定，同样是 0。`extractExecutionRecordsAfter` 只暴露命令级 `isError` 与输出，**不携带**区分二者所需的信号，故 `paired && !isError` 对全部伪造构造放行。
2. **冻结 fixture 根本不带 `tool_result`**（`TOOL_USE` 只产 `tool_use` 块）。把执行证据设为改名跟随硬前提会把 F224「SC-005 真实改名到非规范名 → exit 0」从放行翻成 exit 2。

**结论**：判据来源留在**命令文本**层，但形态必须换。

## 关键设计发现二：为何不用「结构黑名单」，也不用「结构白名单」

- **黑名单**（枚举坏形态并抑制：`nestDepth`/`keywordDepth`/`conditionalPending`）被 Codex 设计阶段用真实 bash 以 **11 条 CRITICAL 反例**证伪：`&&`/`||` 后换行是语法续行不复位、`|&` 原子操作符、`exit 0; mv`（顶层但不可达）、heredoc 正文、`case x in done)` 与参数位 `}` 与 heredoc 内 `fi` 都能**伪造 closer** 清空深度计数、`time`/`!`/`coproc` 前缀与 `for((`/`if<` 让 opener 漏检、运行期 alias。**任何按 closer 递减的深度计数器都可被伪造 closer 欺骗**。
- **结构白名单**（「整条命令是否为简单命令序列」：分隔符 / 分组替换 / 命令位保留字与危险内建 / heredoc 剥离 / 词法平衡五条规则）实施后，又被逐轮找出 **7 条 CRITICAL**（详见「逐轮审查记录」）。Codex 终审判「不宜合入」并指出根因：**该判据本身等于手写半个 bash 解析器**，每个缺口（定界词保真、续行与 heredoc 的处理顺序、注释状态、引号剥离、赋值/重定向前缀、`builtin`/`command` wrapper、语法邻接校验）都是一条新的误放行路径——与黑名单**死于同一模式**，只是高一层。

**最终结论（用户拍板）**：放弃"判断命令是否会执行"这一开放式目标，改为**只认一个可人眼校验的字面形态**。

## 修复策略（最终采纳 · 极窄字面白名单）

`scanRenameCommandEvents(command)` 的判据收敛为一条不变量：

> **产出改名事件 ⟺ 整条 Bash 命令就是一条能证明发生 `SRC→DST` 的光杆改名。**

实现为**无回溯的 token 化校验**（不是正则整体匹配——第 8 轮证明锚定正则的相邻空白量词有 O(n²) 灾难性回溯）：

1. 用 `isShellWhitespace`（**只有** 空格 / tab / `\n`，**不含 `\r`**）做**双向线性扫描**剥离首尾空白，并记录 `leading` 供 offset；剥离与计数共用同一谓词，由构造保证字符集不分叉。
2. 剥离后文本若含 `\n` 或 `\r` → 拒绝（内部换行=多命令；CR 不是 bash 分隔符）。
3. 按 `[ \t]+` 切 token。命令名须为 `mv` 或 `git mv`。
4. **按命令类型拆分的严格 option 白名单**：裸 `mv` 只接受短选项 `^-[fv]+$`（长选项是 GNU 专有，BSD/macOS `/bin/mv` 会 `illegal option` 而不改名）；`git mv` 额外接受 `--force` / `--verbose`。其余一律拒绝（`-n`/`--dry-run`/`--no-clobber`/`--`/未知长选项/含 `f``v` 之外字符的捆绑）。
5. 操作数须**恰好 2 个**，各自匹配 `^[A-Za-z0-9._/-]+$`，且通过路径合法性校验：无 `.` / `..` / 空 segment（含绝对路径）；**dst 不得尾随 `/`**；src 与 dst 不得**互为路径前缀**（父/后代关系）；二者 ASCII 大小写折叠后不得相等。
6. `paramText` 取剥离后文本中命令名之后的**原始子串**（保留空白形态），交既有 `parseRenameOperands` 做第二道校验（带参 option / 多操作数仍整条拒绝）；`offset = leading`。

**不做**行连接消解、**不做** heredoc 剥离、**不**扫描命令位、**不**枚举保留字或内建、**不**校验 shell 语法——这些都因"整条命令不是光杆改名"而自动落空。

### Soundness 论证

若整条命令就是一条带**字面路径**操作数的 `mv`/`git mv`，则它是该 Bash 调用中**唯一**的命令，必然被父 shell 求值。无需推理控制流可达性，无需建模 heredoc / 引号 / 注释 / 内建 / 重定向 / 语法合法性——因为任何多命令、任何元字符、任何引用构造、任何语法错误都**不再匹配**。

这把 soundness 的依据从「穷举坏形态」（黑名单）或「模拟 bash 语法」（结构白名单）改为「**只认一个字面形态**」，故 Codex 五类家族及其全部变体一次性关闭，`exit` / `readonly` / `builtin` / `command` / 赋值前缀 / 重定向前缀 / 引号剥离 / alias 触发词等**根本不需要枚举**。

### `<PATH>` 字符集与路径关系校验都是判据必要组成，不可放宽

- **字符集**：若允许 `;` 等元字符进入操作数，`mv A B;` 会解析出 dst=`B;` → 不符合 `NNN-fix-<name>` → `ambiguous=true` → 重开 fail-open。字符集本身即防线（沿用 F229 教训：判据里任何非必要的宽松都是逃逸面）。
- **路径关系校验（第 10 轮补齐）**：仅靠"形态像一条 mv"不足以证明发生了 `SRC→DST`。四类经真实 `mv`/文件系统实测的反例都**形态合法却根本没改名**——dst 尾随 `/`（不存在则 rc=1，存在则落点是 `DST/basename(SRC)`）、dst 是 src 的父目录（`-ef` 同一目录）、dst 是 src 的后代、大小写折叠后同路径（本机同 dev 同 inode）。这些**都能从命令文本静态判定**，故不属于"运行时不可区分"的已接受残留，必须在判据内关闭。
- **option 白名单必须按命令拆分**：`--force`/`--verbose` 是 GNU coreutils 专有，Darwin `/bin/mv` 实测 `illegal option -- -`、rc=64、无改名；而 `git mv` 支持它们。共用一张表就等于在 macOS 上放行一条确定不改名的命令。

### 保持不动

`parseRenameOperands`（继续提供多操作数保守拒绝）、`splitCommandTextSegmentSpans`、`scanArtifactPath` 提名侧、`resolveFeatureDirCandidate` 状态转移与返回形状、`judgeCompliance`、judge 层降级下界（F230 第 2 层）。结构白名单时期引入的 `blankHeredocBodies` / `isSimpleRenameSequence` 及其常量在新判据下不可达，按仓库「删除死代码」约定整体删除。

## 设计决策记录（用户四次拍板）

1. **判据来源留在命令文本层、不用执行证据**（执行证据实测证伪 + 会破坏 F224 冻结 fixture）。
2. **`&&`/`||` 条件右侧均收紧**（「连 && 一起堵」）：`true || mv` 与 `false && mv` 同类伪造，只堵 `||` 则换 `&&` 即绕过。
3. **黑名单 → 结构白名单**：Codex 11 条真实 bash 反例证明"抑制嵌套 mv"不可采纳。
4. **结构白名单 → 极窄字面白名单（最终）**：Codex 终审又给出 5 类新家族并判「不宜合入」，根因是该判据等于手写半个 bash 解析器。收敛为「整条命令必须就是一条光杆改名」，多一个字符都不跟随。

## 5-Why 根因追溯

| 层级 | 问题 | 发现 |
|------|------|------|
| Why 1 | 死控制流里的 mv 文本为何触发 fail-open？ | 在命令位扫出 mv 即产出改名事件 → 候选跟随非规范名 → `ambiguous=true` → judge fail-open |
| Why 2 | 为何死分支里的 mv 被当命令位 mv？ | 判据下界是「mv 处于语法命令位」，不问该命令位是否可达 |
| Why 3 | 为何 F230 未收口？ | F230 判断「唯一可靠修法是执行证据」并外推为独立 Feature；但执行证据实测不可行 |
| Why 4 | 为何"抑制嵌套 mv"与"判断是否简单命令序列"都不够？ | 二者都要求判定器**理解 bash**——前者穷举坏形态、后者手写解析器；bash 语法面过大，每个缺口都是误放行 |
| Why 5 | 那什么才是可靠下界？ | **只认一个字面形态**：整条命令就是一条光杆改名。判定器不需要理解 bash，只需要做一次锚定匹配 |

**Root Cause**：改名事件的产出下界被定义为一个**需要理解 bash 语义**才能判定的开放集合（先是"命令位"，后是"简单命令序列"），而 bash 的语法面（控制流、替换、引用、内建、前缀、heredoc 词法、续行交互、语法错误）远超任何手写扫描器的建模能力；下界与真实语义的每一处分歧都是一条可主动构造的误放行路径。

## 逐轮审查记录（审计轨迹 · 防后人重蹈）

### 设计阶段（Codex，对黑名单初稿）

11 条 CRITICAL 全部经编排器复核成立 → **黑名单作废**，改结构白名单。要点：`&&`/`||` 换行续行、`|&`、`exit 0; mv`、heredoc 正文、`case … done)` 伪 closer、参数位 `}`、heredoc 内伪 `fi`、结构 underflow、`time`/`!`/`coproc` 前缀、`for((`/`if<` 边界、运行期 alias。

### 第 2 轮（verify 阶段 WARNING → 主线升级为 CRITICAL）

verify 子代理报「`$'…'`（ANSI-C quoting）未建模」并称自造 payload 均被安全拒绝、**未找到实例**。编排器**不采信"未发现即安全"**，byte-exact 复核确认真 CRITICAL：`echo $'a\'; mv S D\'b''` 在 bash 是语法错误（不执行），但 `$'…'` 内 `\'` 是转义字面引号（串继续）而扫描器按 POSIX `'…'`（无转义）配平，两模型分歧使 bash-未闭合的命令在扫描器看来已配平，**绕过 F230 R4-3「未闭合引号不采信」这条已声明关闭的保护面**。

> **方法论教训**：子代理"我构造了 payload 但没找到实例"**不等于**该维度安全。判据与 shell 真实语义存在已知分歧时，必须由主线用真实 shell byte-exact 复核**分歧本身**。

### 第 3 轮（Codex 终审提示方向 → 主线确认）

`blankHeredocBodies` 有意**保留闭合定界词行**，而**引号定界词的值可含空格** → 被保留的终止行与一条真实 `mv <候选> <非规范名>` 命令文本完全同形：`cat <<'mv S D'` ⏎ `body` ⏎ `mv S D`（bash `-n=0`、mv 不执行）被判 `simple=true` + 1 事件 → fail-open。

> **教训**：预处理里**任何"我保留/我豁免这一部分"的决定都是一处新的可构造面**（F229「判据里任何非必要形态约束＝逃逸面」在预处理层的同构表现）。

### 第 4 轮（主线自查，fail-closed 方向 bug）

`<<<` herestring 被误当 heredoc（与该分支注释声明矛盾）、`blankHeredocBodies` 缺 `#` 注释分支——二者都让**真实**改名被漏跟随；修 BUG-1 后又暴露 `<<<<` 退化成合法形态造成的新 fail-open，需补重定向串合法性校验。**这一轮本身就是"手写解析器"treadmill 的实证**。

### 第 5 轮（Codex 终审，对结构白名单最终 diff）

判 **「不宜合入」**，5 类新 CRITICAL 家族（均真实 bash 实测、shim 未调用）：

| 家族 | 代表构造 | 为何绕过 |
|---|---|---|
| 危险内建只按原始首 token 匹配 | `X=1 exit 0; mv`、`>/dev/null exit 0; mv`、`'exit' 0; mv`、`builtin exit 0; mv`、`command exit 0; mv`、`ex\it 0; mv` | 未处理赋值前缀 / 重定向前缀 / quote removal / wrapper / 转义——**「内建 exit 已关闭」的声明不成立** |
| 其他内建仍可改父 shell | `readonly X=0; X=1; mv`、`declare -r X=0; X=1; mv` | 直接证伪「非黑名单命令在子进程运行、不改父 shell」这一 soundness 前提 |
| 不校验 shell 语法 | `printf x >; mv`、`mv S D \|&`、`cat <<; mv` | 三条 `bash -n=2`、解析阶段即失败、整段不执行，却全被接受 |
| heredoc 定界词保真 | `cat <<EOF-X` ⏎ `EOF` ⏎ `mv` ⏎ `EOF-X` | 定界词只取 `[A-Za-z0-9_]+` 前缀 → 提前伪闭合 |
| 续行与 heredoc 处理顺序 | `cat <<'EOF'` ⏎ `EO\` ⏎ `F` ⏎ `mv` ⏎ `EOF` | 全局 unfold 先于 heredoc 识别，把 `EO\`+`F` 合成伪终止符（quoted heredoc 内 bash 不处理续行）|
| 注释内 heredoc 擦除安全标记 | `# <<EOF` ⏎ `exit 0` ⏎ `EOF` ⏎ `mv` | 幽灵 heredoc 把 `exit 0` 当正文空白化 → **由 fail-closed 翻成 fail-open** |

Codex 另有 2 条 WARNING（真实合法却被误阻断）：`mv S D && true` / `mv S D; exit 0` / `mv S D; if true; then :; fi`（mv 在**左侧**、必然执行）；`cat <<EOF-X` 合法用法因定界词截断而 `balanced=false`。二者在最终形态下**统一变为"非光杆即不跟随"**，语义一致且已文档化。

Codex 同时确认（Info）：`offset`/时序在受支持子集内正确、冻结面成立（core 392/392、SC-005 与 SC-005b 结论不变、裸 `git mv` 仍产出事件）、无越界与灾难性回溯（1 MiB ≈ 57ms）。

### 第 6 轮（主线自查，误阻断）

收敛后的锚定形态对 `mv S D\n`（**尾随换行**）不匹配 → 零事件 → 真实光杆改名被漏跟随 → 误阻断一次合法收口。真实 transcript 的 Bash `command` 常带尾随换行，而 `mv S D\n` 在 bash 里就是同一条命令（空行为 no-op），故放宽为「剥离整条命令**前后**的空白后再整体匹配」，命令**内部**换行仍一律拒绝。

### 第 7 轮（主线自查，CRITICAL 误放行）

第 6 轮用 `raw.trim()` 实现剥离，而 **JS `trim()` 剥除全部 Unicode 空白**，**bash 只把 空格/tab/换行 当 token 分隔符**。于是"bash 会判 command not found、mv 根本不执行"的命令被 `trim()` 归一成合法光杆 mv。实测 6 个前导字符（`\v` U+000B、`\f` U+000C、NBSP U+00A0、U+2028、BOM U+FEFF、U+3000 全角空格）全部产出 1 条事件 → `ambiguous=true` → **fail-open**；真实 bash 一律报「`$'\vmv': 未找到命令`」、mv 不执行。附带缺陷：`leading` 用 `/^[ \t\r\n]*/` 计数而剥离用 Unicode 全集，**两个字符集不一致**导致 `offset` 错位（`\v` 形态 offset 指向 `\v` 而非 `mv`）。

**收口**：剥离改为只剥 `[ \t\r\n]`，并让 `leading` 与剥离**共用同一字符集**（由构造保证一致，而非靠人记得同步）。修复后上述 6 形态一律 `[]`（fail-closed，与 bash 语义一致），第 6 轮的合法边界全部保留。

### 第 8 轮（主线自查，CRITICAL 可用性 / DoS —— 本次改动引入的回归）

锚定形态里相邻空白量词 `(?:[ \t]+-[A-Za-z-]+)*[ \t]+…` 存在歧义切分，造成**灾难性回溯**。实测 `'mv' + ' '.repeat(n) + 'x'`：

| n | 耗时 | 增长比 |
|---|---|---|
| 10,000 | 51.7ms | — |
| 20,000 | 163.9ms | ×3.2 |
| 40,000 | 641.7ms | ×3.9 |
| 80,000 | 2,661.9ms | ×4.1 |
| 400,000 | **64,946ms（65 秒）** | — |

清晰 O(n²)。变体同样中招（tab 代替空格、第一操作数合法、**乃至"能匹配成功"的形态**均为数百 ms/40KB），故不止失败路径慢。

**为何是 CRITICAL**：判定器跑在**同步 Stop hook**。会话只需发一条含大段空白的 Bash 命令即可让门禁挂住数十秒 → 门禁不可用 / 宿主超时 → 可能异常 fail-open。本仓库有明确先例（F227 候选历史 O(N²) 致 11.8s 被当 DoS 面修掉并留下性能锚点）。**这是本次改动引入的回归**——HEAD 的 F230 扫描器是单趟线性状态机，无此问题；证明"用一条正则替掉状态机"虽简化了语义面，却引入了新的复杂度面。

**收口**：改为**无回溯的 token 化校验**（剥首尾空白 → 拒绝内部换行 → 按 `[ \t]+` 切 token → 校验命令名 / 可选 flag / 恰好 2 个字面路径），语义与锚定形态逐字等价，`paramText` 仍取 `stripped` 中命令名之后的原始子串（保留原空白形态，供 `parseRenameOperands`）。刻意**不用**"加长度上限"绕过——R4-4 已证明长度上界本身可成为绕过通道，且"可匹配形态也慢"意味着上限会误伤合法长命令。同时新增性能回归锚点（400k 空白 → 零事件且有界耗时），防回溯复发。

### 第 9 轮（Codex 终审对收敛后 diff）：前五类确认全关，新增 3 类 CRITICAL

Codex 逐条复验确认**第 5 轮那五类家族已由整体字面匹配全部关闭**（`X=1 exit` 等 6 条、`readonly`/`declare -r`/`typeset -r`、`printf x >;` 等语法错误、`<<EOF-X` 与引号定界词、quoted heredoc 续行与 `# <<EOF`——真实 bash 逐条 `MV_RAN=false`，判定器全部零事件），且确认 Unicode 空白漏洞已关、offset 全部精确、删除符号零生产残留。但**新预处理与仍保留的 option / path 语义又形成 3 个分歧点**（编排器已在主线用真实 bash / git / coreutils 逐条复现确认）：

| # | 家族 | 真实语义（实测）| 修复前判定 |
|---|---|---|---|
| 1 | **CR 不是 bash token 分隔符** | 前导 `\rmv S D` → `$'\rmv': 未找到命令`、**mv 不执行**；尾随 `mv S Y\r\n` → mv 执行但**实际创建的目录是 `901-fix-y^M`（带 CR）** | 前导：产出事件 → fail-open；尾随：剥掉 CR 后**记录了一个并不存在的路径** |
| 2 | **option 白名单过宽** | `git mv -n` / `--dry-run` 明确**不改名**（实测 dry-run 后目录未变）；`mv --definitely-invalid` / `-vt` / `-tfoo` 报 illegal option、exit 64、**无改名** | 全部产出事件 → `ambiguous=true` → fail-open |
| 3 | **规范化后与源相同的目标** | `mv specs/X specs/./X` → rc=1 `Invalid argument`、**目录未变**（`-ef` 确认同一目录）；`specs//X`、`specs/../specs/X` 同类 | 解析出非规范 dst → `ambiguous=true` → fail-open |

**第 1 条的责任在编排器**：第 7 轮的收口指令把 `SHELL_WHITESPACE_CLASS` 写成 `[ \t\r\n]`，而 bash 只把 空格/tab/换行 当 token 分隔符，`\r` 是普通字符。这说明**即便是"修分歧"的那一轮，也可能引入新的分歧**——订正为 `[ \t\n]`。

**更值得记的是它如何被掩盖**：当轮测试把 `mv S Y\r\n` 断言为"跟随到无 CR 的 `901-fix-y`"，于是 448/448 全绿却掩盖了 soundness 漏洞。**测试断言本身编码了错误的 shell 语义时，绿色是反指标**——这与 F229「超集要穷举，不能靠『测试全绿』」同源。

**收口**：字符集去掉 `\r`；option 收为严格白名单（只认 `-f`/`-v`/其 `f`/`v` 捆绑与 `--force`/`--verbose`，拒绝 `-n`/`--dry-run`/`--no-clobber`/`--`/未知长 option/含其他字符的捆绑）；操作数按 `/` 切分后拒绝 `.`／`..`／空 segment（允许单个尾随斜杠）。三条均落在第 8 轮的 token 化实现里，天然是逐 token 常数级判定，不重新引入回溯。

### 第 10 轮（Codex 对 token 化 diff 终审）：DoS 与回归全过，新增 4 类 CRITICAL

Codex 确认：**DoS 已根治**（400KB/1MiB 全链路线性，各路径 0.13–33ms，输入涨 2.62× 耗时涨 2.4–2.7×）；**空白字符集本轮正确收口**（VT/FF/NBSP/U+2028/BOM/U+3000/CR 的前导/内部/尾随 21 组构造全零事件）；offset 精确；SC-005 / SC-005b / 真实会话 67720241 只读 report 实跑结论不变；F225 提名侧未受影响；删除符号无运行时残留；被翻转的断言方向全部是"更严"。

但仍有 4 类**形态合法却根本没发生 `SRC→DST`** 的构造（均真实工具实测，且**都可从命令文本静态判定**，故不属于已接受的"运行时不可区分"残留）：

| # | 构造 | 真实语义（实测）|
|---|---|---|
| C1 | `mv SRC specs/renamed-nonstandard/`（**dst 尾随 `/`**）| dst 不存在 → rc=1 无改名；dst 存在 → 真实落点是 `DST/basename(SRC)`。**两种情况都不是 `SRC→DST`** |
| C2 | `mv specs/230-fix-x specs`（dst 是父目录）/ `mv X X/child`（dst 是后代）| shim 实测 `EXISTING_PARENT_SAME_FILE_NO_RENAME` rc=74 / `DESCENDANT_NO_RENAME` rc=75，`-ef` 确认同一目录 |
| C3 | `mv specs/230-fix-x SPECS/230-fix-x`（大小写别名）| 本机同 dev 同 inode、`-ef=yes`、`SAME_FILE_NO_RENAME` rc=73 |
| C4 | `mv --force …` / `mv --verbose …` | 长选项是 GNU 专有；Darwin `/bin/mv` 实测 `illegal option -- -`、rc=64、**无改名**（`git mv` 则支持）|

**第三次出现"绿色测试掩盖漏洞"**：`mv --force`/`mv --verbose` 与 `mv S/ Y/` 两组**正向**断言编码了错误的真实命令语义（测试只调纯函数、从不真跑 `mv`），于是 926/926 全绿反而把误放行固化进回归集。这与第 9 轮的 CRLF 正向断言同型——**判定器的测试若只验判定器自己，就无法发现"判据与真实工具语义不一致"**。

**收口**：dst 不得尾随 `/`（src 可以）；src/dst 不得互为路径前缀（按 segment 边界判定，避免 `900-fix-x` 与 `900-fix-xyz` 误判）；ASCII 大小写折叠后不得相等；option 白名单按命令拆分（裸 `mv` 只认短 `-f`/`-v` 及捆绑，`git mv` 另加 `--force`/`--verbose`）。两条错误正向断言翻正，并新增 `git mv --force`/`--verbose`、`mv S/ Y`（仅源尾随斜杠）为正向。

### 第 11–12 轮：`DST 已存在 → 嵌套搬入` 的探针方案被实测证伪并回退

**第 11 轮**：Codex 指出 `mv SRC DST` 当 **DST 运行时已是目录**（不带尾随斜杠）时，真实落点是 `DST/basename(SRC)`——命令文本与合法改名逐字相同、静态不可判定。编排器提出并实现「注入式磁盘**否证**探针」（core 保持零 I/O，judge 注入 `isNestedMoveTargetOnDisk`，探到 `dst/basename(src)` 存在即拒绝跟随），论证是"F227 失败在用磁盘**证明**事件，这里是**否证**，方向相反"。

**第 12 轮：该论证被编排器自己的实测证伪，方案整体回退。** 两条实测：

| 方向 | 构造 | 实测结果 |
|---|---|---|
| **假阴（关不掉漏洞）** | 嵌套发生后，攻击者下一条命令把 `DST/basename(SRC)` 搬走；终态只剩 `DST` | 探针返回 `false` → 改名照常跟随 → `{path:null, ambiguous:true}` **fail-open 完全恢复** |
| **假阳（误阻断合法改名）** | 合法 `A→B`，但 `A` 原本含同名子目录 `A/A`；终态存在 `B/A` | 探针返回 `true` → `{path:'specs/900-fix-x'}`，**真实改名被拒绝跟随** |

**根因**：Stop hook 在会话末尾重放整段 transcript，而探针读的是**单一终态快照**——**终态同样在攻击者控制之下**。故 F227「终态存在性 ≠ 历史事件是否发生」对**否证方向同样成立**：否证需要"证据仍在"，而攻击者可以删证据。这是本 Feature 第二次栽在同一条原理上（第一次是 F227 三版方案），值得单列。

**且该风险本就不提供新能力**（实测）：
- **劫持既有规范目录、消费他人制品**：纯提名即可，**完全不需要 mv**——`Write specs/999-fix-decoy/fix-report.md` 实测得 `{path:'specs/999-fix-decoy', ambiguous:false}`，与嵌套路线**逐字相同**。这就是 F227 已知限界一（用户已明确知情并接受）。
- **打开 fail-open 降级**：真实 `git mv S <非规范名>`（目标不存在）实测得 `{path:null, ambiguous:true}`——这就是 SC-005、F224 的**设计意图**、用户明确要求保住。

故「DST 已存在 → 嵌套搬入」不构成新增攻击面，写入已知限界即可（见限界 2d）。

**回退范围**：删除 core 的 `options.isNestedMoveTarget`（恢复 `(entries, anchorLineIndex)` 两参零 I/O 纯函数与 F227 显式契约）、io 的 `isNestedMoveTargetOnDisk`、judge 的注入点。**第 11 轮的测试质量改进全部保留**（受控 env 防 shim 假绿、内容哨兵、git 隔离、清理修复、`git mv -fv/-vf`/`git mv S/ Y` 覆盖）；预建 DST 的三条差分用例改写为**已知限界 characterization**（钉住真实嵌套语义 + 判定器当前行为 + 为何不是缺陷），标题明确写"已知限界"而非"反向回归"，避免后人误读为已关闭。

### 贯穿七轮的根因模式（最重要的一条泛化教训）

本 Feature 共出现 **4 次误放行 CRITICAL**（`$'…'` 引号配平、heredoc 闭合行保留、结构白名单的 5 类家族、Unicode 空白剥离），根因**同一个**：

> **判定器内部某个"模型"与 bash 真实语义存在分歧，而分歧点本身就是一条可主动构造的逃逸路径。**

分歧的具体载体逐轮不同（引号配平规则、预处理里"我保留这一部分"的决定、"什么算简单命令"的语法建模、"什么算空白"的字符集），但形状一致。由此得出三条可操作约束：

1. **判据宁可极窄，不可"近似理解 bash"**——凡需要判定器理解 shell 语法才能成立的判据，都会在某个缺口处误放行；只认一个可人眼校验的字面形态才收敛。
2. **禁止用 JS 内建的 Unicode 语义近似 shell 语义**：`trim()`、`\s`、`\b` 的字符集都比 shell 的 token 分隔符宽，每一处都是分歧点。
3. **归一化 / 剥离 / 豁免所用的字符集必须与消费它的判据共用同一定义**，由构造保证一致；两处各写一遍就等于埋一颗迟早分叉的雷。
4. **只验判定器自己的测试，发现不了"判据与真实工具语义不一致"**（第 9/10 轮各栽一次，共三次）：本模块的单测全部只调纯函数（`scanRenameCommandEvents` / `resolveFeatureDirCandidate`），**从不真正运行 `mv`/`git mv`**。于是 `mv S Y\r\n`「跟随到无 CR 的目录」、`mv --force`「必须跟随」、`mv S/ Y/`「跟随到 Y」三组**正向**断言各自编码了错误的真实命令语义，让 448/448、926/926 全绿反而把误放行固化进回归集。**全绿在这里是反指标**。对策：凡断言"某形态是真实改名"，其正确性依据必须来自**真实工具实测**（真临时目录 + 同名 shim + `bash -n`），并把实测结论写进用例注释；判定器的测试**不能只以判定器为准**。
5. **判据"变简单"不等于"变安全"——简化语义面时要同时看复杂度面**（第 8 轮）：用一条正则替掉线性状态机确实把可分歧的**语义**面压到最小，却引入了状态机本来没有的**灾难性回溯**面。安全门禁跑在同步 Stop hook 上，可用性即安全属性（挂死 → 门禁不可用 → 可能异常 fail-open），故任何新判据都必须同时给出**最坏复杂度**证明与性能回归锚点，不能只证明"判得对"。

这是 [[F229]]「判据里任何非必要形态约束＝逃逸面」的推广形式：**不只是判据本身，判据的每一处预处理与归一化同样是逃逸面。**

## 冻结语义保全清单

**照常跟随（光杆形态）**：`mv S D`、`git mv S D`、`mv -f S D`、`git mv -f S D`（C1/C2/C3）。

**必须保住的端到端**：
- **F224 SC-005**：单条裸 `git mv <FEATURE_DIR> specs/renamed-nonstandard` → `exit 0` 降级、落盘 `compliant:null` + `degraded:true` + 诊断含 `feature-dir-unresolvable`（该命令是光杆形态，匹配 → 照常跟随）
- **SC-005b**：零委派 + 单条非规范 `git mv` → `exit 2`
- **真实会话 67720241** → `compliant:true`（其 mv 在 heredoc JS 数据内 → 整条命令非光杆 → 零事件 → 候选停留 → F227 兜底回落真实目录）
- F225 提名侧同段共现、F227 候选历史与性能、F228/F229 判据用例全绿

**改为不跟随（全部朝更严方向，逐条更新断言并注明理由）**：C4（`cd . && mv`）、C5（heredoc 后 mv）、C6/C6b/C6c（`;`/`|`/`&` 两跳链）、`mv A B # 注释`、以及 F230 直测中期望产出事件的多命令 / 含引号形态（`mv a b; mv b c`、`mv a b | mv b c`、`mv src "dst;mv a b"`、`mv src dst\;mv a b`、`git\nmv a b`、`true # ; mv a b\nmv c d`）、R3-C4 时序 characterization（`mv A B; printf x > A/fix-report.md`）。

## 已否决方案

- **执行证据（`paired && !isError`）**：对全部伪造构造放行 + 翻掉 F224 冻结 fixture（见「关键设计发现一」）。
- **磁盘核验改名目标存在性**：F227 三版证伪（历史事件序列 vs 终态快照自相矛盾）+ F224 SC-005 磁盘无制品仍须 exit 0。
- **结构黑名单**：Codex 11 条真实 bash 反例，伪 closer 可欺骗任何递减深度计数器。
- **结构白名单（简单命令序列判定）**：Codex 终审 5 类新家族 + 判「不宜合入」；根因是手写 bash 解析器不可能穷尽。
- **磁盘终态"否证"探针**（第 11 轮实现、第 12 轮回退）：见「第 11–12 轮」节。**它与 F227 的「磁盘终态证明」是同一个错误的两面**——只要终态在攻击者控制之下，"否证"所依赖的证据同样可被抹除（假阴），而"证明"与"否证"都会因终态含义歧义而误伤合法路径（假阳，本例是 `A` 原含同名子目录 `A/A`）。
  **由此得到的判据锚点原则**：判据要么锚在 **transcript**（会话结束时不可事后篡改的历史记录），要么锚在**带外可信证据**；**不能锚在可变的磁盘终态**——无论用它做正向证明还是反向否证。

- `contracts/fix-compliance-judge-cli.md` 场景表：核对是否需补「非光杆改名命令不触发降级」一行

## 已知限界（如实记录，不得表述为已解决）

**总括**：最终判据是**一个字面形态匹配**，不是 shell 解析器，也不声称能证明"mv 在运行时真的完成了改名"。它的可靠性来自**极窄**：整条命令必须就是一条光杆改名，故所有已知伪造家族（控制流 / 替换 / 分组 / 前缀 / 内建及其赋值-重定向-引号-wrapper-转义变体 / heredoc 词法 / ANSI-C 引用 / 语法错误 / 外部终止符）都因"不是光杆"而一次性关闭。残留只有下列两类，**方向分明**：

### A. 误阻断方向（安全，代价是可能冤枉一次合法收口）

1. **任何非光杆形态的真实改名不被跟随**：`X && mv`、`mv && X`、`mv; exit 0`、`( mv )`、`{ mv; }`、`time mv`、`sudo mv`、`FOO=1 mv`、`command mv`、`xargs mv`、`mv A B 2>&1`（带重定向）、`cat > <制品> <<EOF … EOF` 换行 `mv`（写制品与改名同命令）、`mv A B; mv B C`（同命令多跳）、`mv A B # 注释`（带尾注释）、操作数含引号 / 空格 / `$VAR` / 非 `[A-Za-z0-9._/-]` 字符的路径。后果：候选停在旧路径 → 撞磁盘核验报「未建立特性目录」→ exit 2。
   **缓解**（应写入 SKILL 指引）：把改名单独写成一条 `git mv <字面旧路径> <字面新路径>` 命令即照常跟随。特性目录命名规范 `specs/NNN-fix-<name>` 本身只含 `[a-z0-9-/.]`，天然落在允许字符集内。
   刻意**不做**前缀 / 构造白名单——白名单里再开白名单即新的可构造面（本 Feature 五轮的核心教训）。

1b. **第 10 轮新增的四类误阻断（均为 fail-closed 取舍，逐条写明代价）**：
   - **dst 尾随 `/`**（`mv SRC specs/new/`）不跟随。该形态是**状态依赖**的：实测 dst 不存在时 `/bin/mv` 精确改名（rc=0），dst 已存在时落点变成 `DST/basename(SRC)`。判定器无法知道磁盘状态，故一律拒绝。**（订正早期措辞）** 它不是"必然无改名"——拒绝的理由是"**无法证明**发生了 `SRC→DST`"。
   - **src 与 dst 互为路径前缀**（`mv specs/X specs`、`mv X X/child`）不跟随。真实 mv 在这两种关系下都不改名（rc=2 `are identical` / rc=1 `Invalid argument`），**拒绝无代价**。
   - **ASCII 大小写折叠后相同**（`mv specs/x SPECS/x`）不跟随。在**大小写不敏感** FS（macOS 默认）上真实同 inode、确无改名；在**大小写敏感** FS（Linux ext4）上二者是不同目录、会发生真实改名 → 该平台上属**误阻断**。刻意选 fail-closed（宁可在 Linux 上误阻断一次，不在 macOS 上放行一条 no-op）；差分测试对该条做运行时探测，仅在不敏感 FS 上断言磁盘事实，避免在 Linux CI 假红。
   - **裸 `mv` 的长选项**（`mv --force` / `--verbose`）不跟随。它们是 GNU coreutils 专有：Darwin `/bin/mv` 实测 `illegal option -- -`、rc=64、无改名；GNU/Linux 上则合法且会真改名 → 该平台上属误阻断。取**跨平台交集**（裸 `mv` 只认短 `-f`/`-v` 及其捆绑），`git mv` 因跨平台一致而保留 `--force`/`--verbose`。

### B. 误放行方向（危险，如实标注为固有上界，非本次可闭合）

2. **命令文本是光杆 `mv`，但 `mv` 在运行时未真的改名**：
   - **名称遮蔽**：环境中预置 `alias mv=…` 或同名 shell function / PATH 中优先的 `mv`，使这条命令不执行真实改名（非交互 bash 默认 `expand_aliases` 关闭，function/PATH 遮蔽需预置环境，门槛高）。
   - **运行时失败**：源不存在 / 权限不足 / 跨设备失败等，命令文本合法但改名未发生。
   二者**与 F224 的既有前提同源**：F224 本就接受"真实执行的改名可打开降级通道"，而"看起来是真实改名但运行时没成功"在**命令文本层不可区分**（F230 亦已指出「连 `mv A B` 单独一条也可能运行时失败」）。彻底关闭需要可信的运行期完成证据，而 `tool_result` 对静默 mv 无区分力（见「关键设计发现一」）——须另立 Feature 重设 `ambiguous` 的 fail-open 证据合同，本次不佯装闭合。

2d. **`mv SRC DST` 当 DST 运行时已是目录 → 真实落点是 `DST/basename(SRC)`，判定器仍按 `SRC→DST` 跟随**（第 11–12 轮；属上条 2 的具体实例，但**构造成本远低**，故单列）：命令文本与合法改名逐字相同、**静态不可判定**；「查磁盘嵌套特征」的探针方案已被实测**证伪并回退**（假阴：攻击者删掉嵌套证据即失效；假阳：`A` 原含同名子目录 `A/A` 时误阻断合法改名——详见「第 11–12 轮」节）。
   **为何仍可接受**：该结果**不提供超出既有两条已接受限界的新能力**（均经实测）——(a) DST 是既有规范特性目录时，攻击者**纯提名**即可达成逐字相同的结果（`Write specs/999-fix-decoy/fix-report.md` → `{path:'specs/999-fix-decoy', ambiguous:false}`），即 **F227 已知限界一**（用户已明确知情并接受）；(b) DST 是非规范名时，攻击者真实改名到一个**不存在**的非规范名即可打开同一条降级通道，即 **SC-005 / F224 的设计意图**（用户要求保住）。故它不是新增攻击面，而是这两条既有限界在另一种命令形态下的同构表现。
   彻底关闭同样须重设 `ambiguous` 的 fail-open 证据合同，留作独立 Feature 候选。

3. **`parseRenameOperands` 的 `\s+` / `trim()` 是"靠调用方构造保证安全"的耦合不变量（潜在隐患，本次不改）**：该函数用 `String(segment).trim().split(/\s+/)` 分词，即它**把 NBSP / `\v` / U+2028 等 Unicode 空白也当操作数分隔符**（实测 `parseRenameOperands('specs/a<NBSP>specs/b')` 返回两个操作数）。当前**不构成漏洞**——全仓仅一个生产调用方（`applyRenameEvent`），其输入 `paramText` 来自锚定形态的捕获组，而该形态的字符集 `[A-Za-z0-9._/-]` 与 `[ \t]` **不可能包含任何 Unicode 空白**（实测：以 NBSP 作分隔的 `mv` 命令整体不匹配 → 零事件）。故安全性由**调用方的字符集**保证，而非该函数自身。
   **维护约束（务必遵守）**：若将来放宽 `scanRenameCommandEvents` 的 token 化判据字符集（`RENAME_PATH_TOKEN_REGEX` 的 `[A-Za-z0-9._/-]`、`isShellWhitespace` 的分隔符集合，或 option 白名单），必须同步收紧本函数的分词，否则第 7 轮的同一类分歧会在操作数解析层复现。本次刻意不改它——它在 `plan.md` 的不改动清单内，且其「多操作数 / 带参 option 整条跳过」是与 token 化判据**叠加**的第二道防线（实测 R4-4 超长空白藏第三操作数已被 token 化判据挡住，两道判据均生效）。

4. **F227 已知限界一（冒用已存在且制品齐全的历史特性目录）** 与本次正交，不在范围。

5. **裸管道 / 后台两跳的并发语义**（Codex C-R1）：`mv A B | mv B C` 两侧并发、非顺序状态转移，既有冻结曾把它当顺序「取最终态」。最终形态下该命令**整体不再被跟随**，该可商榷的 characterization 合同随之退场。
