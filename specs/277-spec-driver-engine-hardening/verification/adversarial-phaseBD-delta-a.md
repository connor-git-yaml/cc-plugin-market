## 新引入缺陷

### N-1（WARNING）步骤 8 第一行是绝对句，未给 smoke 轮 `dist_not_built` 例外留交叉引用 ⇒ 字面执行会停掉每一个缺 dist 的 goal_loop smoke 轮

**构造**：goal_loop `round-1`、`verify_mode=smoke`、全新 worktree（`dist/` 不在盘）。按 `verify.md:472`，build 依赖 e2e 记 `status:"SKIPPED", skipped_reason:"dist_not_built"`。按映射表第 8 行（`:525`）`SKIPPED` → 不通过侧 / 未执行（缺席）；按 `:529` 例外，落侧**保持不通过**（例外只放开阻断）。于是 `合并律结论 = ❌ 不通过`。再读步骤 8 第一行（`:355`）——「**合并律判不通过 → GATE_VERIFY 停下，标记 NEEDS FIX**」，句中无任何例外指针，且自带最强口径「本行是合并结论接到下游动作的唯一落点」。执行者据此在每个缺 dist 的 smoke 轮停在 GATE_VERIFY，与 `:529` 的「**不阻断** goal_loop 的轮次推进」以及既有 `:480`「smoke 轮的 `dist_not_built` SKIPPED 是预期行为……正常放行」直接相撞。

**为什么算新引入**：改前步骤 8 与合并律不接线（这正是 ε-C1 的病），接线后第一次让「落侧」经步骤 8 直通「阻断」这一动作，而例外恰恰是要把这两者拆开的——例外与接线是同一批改动的产物，拆分口径只写在例外那一侧。

**修补方向**：`:355` 行末补一句交叉引用——「**例外**：映射表第 8 行的 smoke 轮 `dist_not_built` 只放开『阻断』、不放开『落侧』，该行不触发本行的 GATE_VERIFY 停下（见「既有取值 → 合并律态的显式映射表」第 8 行的唯一例外）」。或在 `:529` 反向补「本例外放开的『阻断』即指步骤 8 第一行的 `GATE_VERIFY 停下`」，使两处互指。二选一即可，不必两处都写。

### N-2（WARNING）「本次要新造或改写的制品」全篇未界定，两种读法各导出一个坏结果

**命中位置**：`plan-template.md:83` 与 `:94`（三项测试的从严方向）、`agents/plan.md:275`、`agents/verify.md:92`、`agents/spec-review.md:68` —— 五处共用同一句「是否存在一份**本次要新造或改写的制品**承载它」，**没有任何一处说明「制品」的取值域**。

**构造（宽读，自指）**：主张「该 FR 由本次产出的 `verification-report.md` / spec-review 报告承载」。这两份报告每轮必然新造，于是「存在承载制品」**恒真** ⇒ 从严方向把**每一行** `约束型` 判为应判实现型 ⇒ spec-review 抽检对每行都出 CRITICAL「类别误标」。一个恒真判据不区分真假，与 ε-C2 反驳里点名的「恒假合并律」是同一失效形态的镜像；副作用是该 CRITICAL 迅速贬值为噪声。

**构造（窄读，攻击面）**：反向主张「散文条款不由任何『制品』承载，`verify.md` 是被改写的**文件**不是本卡『制品』」⇒「不存在承载制品」⇒ `约束型` 标注成立、抽检记「类别成立」，γ-C3 的四重免检通道原样保留。判据取值域未定时，被检方可自选读法，而**两种读法的选择权在被检方**。

**修补方向**：在 `plan-template.md:94` 的「类别判定依据」处一次性界定并让另外四处指向它——「**制品** = 本卡 `tasks.md` 认领面上、会进 git 的文件（源码 / 测试 / 模板 / agent 散文 / 契约 / fixture）；**显式排除**每轮运行时生成的 `verification/*.md`、spec-review 报告与任何评审产物」。排除句是承重的：不排除即恒真。
