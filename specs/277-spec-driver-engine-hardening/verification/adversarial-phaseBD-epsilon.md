### C-2　合并律的 7 种态与本文件四套既有取值词表不交集，而其兜底句被「新状态」三字限定，接不住既有词表

**A（既有四套词表）**，同文件：

- `:239-243` Layer 1.5 → `COMPLIANT` / `EVIDENCE_MISSING` / `PARTIAL`
- `:268` Layer 1.8 → `RESIDUAL_FOUND`
- `:275` Layer 1.9 → `DOC_DRIFT`

**触发路径**：Layer 1.5 判 `EVIDENCE_MISSING`、Layer 1.8 判 `RESIDUAL_FOUND`、Layer 1.9 判 `DOC_DRIFT`、Layer 2 某命令 `status: UNKNOWN`。逐条问「是否落在 7 种态中的任意一种」——七个态里没有任何一个是这四个取值，答案逐条为「否」。再看兜底句：这四个都不是**新**状态，它们是本文件既有的、比合并律更早存在的取值，兜底句字面上不适用。⇒ 该次交付合并律判**通过**。

**后果**：合并律对本文件四层子检查中的三层（1.5 / 1.75–1.9 / Layer 2 的 SKIPPED·UNKNOWN 面）**结构性失效**。且模板 `verification-report-template.md:85-86` 的逐项回溯表恰恰把这几层列为必填行：

```text
| Layer 1.5 验证铁律合规 | {结论} | {是 / 否} | {是 / 否} |
| Layer 1.75/1.8/1.9 | {结论} | {是 / 否} | {是 / 否} |
```

第 3 列问的是「是否落在 7 种不通过态」——按取值词表，这两行只能诚实地填「否」。**模板把失效路径固化成了必填格式**。

**为什么这条判 CRITICAL 而不是 WARNING**：本次改动**在另一份文件里恰好完整做对了这件事**。`agents/spec-review.md:75-89` 建了「旧值 → 新值显式映射表」，明写「本表覆盖收编前两条判定链的**全部 5 个旧取值**……**缺任一旧值的映射即本收编未完成**」，`:144` 还专门论证了不重映射会让 WARNING 成为「**永不触发的死级别**」。同一批改动、同一个作者、同一类问题，在 `spec-review.md` 识别为必须处理，在 `verify.md` 未做 —— 这是**双标**，不是疏漏可辩护的边界。

**对本条的最强反驳与回应**：可以主张「新状态」在此是「其他状态」的口语写法，不含时间义，故兜底句本就覆盖这四套词表。回应两点：其一，同句括号内又写一遍「**新增状态**不得因『没被列举』而落入通过侧」，两处用词一致指向「后来出现的状态」，把它读成「其他」需要**同时**否定两处；其二，**即便按最宽松读法接受兜底句覆盖了它们**，`COMPLIANT` 与 `PASS` 也会被一并扫进不通过侧（它们同样「未被列举」），使每一次交付恒判不通过——即宽松读法给出的是一个**恒假**的合并律。两条读法各自导出一个坏结论，说明缺的是显式映射表本身，不是读法选择。

**冲突 / 修补方向**：**冲突**。二选一：(a) 在 `verify.md` 补一张与 `spec-review.md:75-89` 同型的「既有词表 → 7 种态」映射表，逐条给出 `EVIDENCE_MISSING` / `PARTIAL` / `RESIDUAL_FOUND` / `DOC_DRIFT` / `SKIPPED` / `UNKNOWN` / `FAIL` 七个既有取值各自落哪一侧；(b) 把兜底句的「新状态」改为「**任何未被本条列举的状态（含本文件既有的 Layer 1.5 / 1.8 / 1.9 / Layer 2 取值）**」。(a) 更好——(b) 会把 `COMPLIANT` / `PASS` 也扫进不通过侧，需再开豁免。
