## 一、被采纳并改变设计的 CRITICAL

### D-1 🔴 锁失败若复用 `saveBlockState().ok=false` 通道 ⟹ `touch` 一个锁文件即首次 Stop 放行

**来源**：绕过面 C1。**主线程复核**：成立，且证据链完整。

`judge:652` 的 `if (saved.ok)` 是**唯一**通往 `return 2` 的门；`ok:false` 走 `judge:662`
`storageUnavailable:true` → `releaseDegraded` → **return 0**。`routeNonBlock` 同构（`judge:780`）。
该分支的安全论证前提是「存储不可用是环境事故、不可自诱发」——而**锁文件在被判方写域内**，
前提直接不成立。这是「载体复用但不重做失效方向论证」的教科书形态。

**处置（已进设计）**：锁不可得 **MUST** 走**独立返回态**（如 `{ lockUnavailable:true }`），
映射到 **`return 2` + 专属诊断码**，**绝不复用** `ok:false`。
并追加不变量：**锁的可得性不得改变裁决方向**（既不额外放行也不额外阻断），
否则被判方获得一条用锁文件操纵裁决的通道。

### D-2 🔴 G4 必须降级为**纯诊断码**，不接路由、不进预算桶（两路独立命中）

**来源**：绕过面 C3（陈旧⟹更宽 是已证伪路线 #21 的**反向同型**：自生成文本换取更宽处置）
+ 误伤面 C-3（真实语料实测该判据近乎恒真，且会**吃光 G2 的预算**）。

误伤面给出本机 **454 份真实 transcript** 的实测：

| 观测 | 结果 |
|---|---|
| 末行**不是** assistant 条目 | **453 / 454 = 99.8%** |
| `join("\n").trim()` 后含换行 ⟹ 裸子串比对失败 | **49 / 454 = 10.8%** |
| 末条 assistant 无 text 块（值来自更早消息） | 5 / 454 |

**归因**：`last_assistant_message` 的构造是**块 join + trim**（F270 `harness-field-probe.md:66`），
与 JSONL 落盘形态不同形；且「尾部」这个位置假设本身不成立。
更要紧的是：F262 已实证本 harness 主 transcript **懒刷盘滞后 25+ 分钟**，
⟹ 该指标度量的是 **harness 刷盘行为**，不是初稿 Why-4 声称要度量的「病根 i 残余误伤率」。

**预算污染（决定性）**：初稿护栏 R-11 要求 G2/G4 两类非计数裁决**同落** `nonBlockStopCount`，
而 `NON_BLOCK_LIMIT = 2`。陈旧判据误触两次即吃光 GATE 去重预算 ⟹ **G4 静默抵消 G2**。

**处置（已进设计）**：G4 = **纯诊断码**，不改变任何路由、不进任何预算桶
（与 P3 对 `stop-hook-reentry` 的终版处理同源）。判据改**集合归属**：
`payload.last_assistant_message ∈ { assistant 条目的 textBlocks.join("\n").trim() }`，
**绝不**用裸子串或「尾部相等」。
**FR-033 仍被完整满足**——它只要求「缺席」与「取到且判定陈旧」分配不同诊断码、
`snapshot-stale` 专码仅用于后者，从未要求改判。卡面验收「专码出现在审计流且与 evidence-missing
可区分」同样只需诊断码。

### D-3 🔴 PENDING **收紧**（FR-031）本卡不做，显式裁剪并登记证据（两路独立命中）

**来源**：误伤面 C-2（三重连锁 + 本仓 190 份真实 verification-report 语料实测）
+ 绕过面 C4（判据是对被判方散文的形态约束，伪造成本 ≈ 10 字 vs 合同成本 ≈ 跑完验证）。

三重连锁（误伤面归因，主线程按代码复核成立）：
1. **推迟通道被整体关闭**：新增独立 missing 键按 `core:875` 纪律**不入** `DEFERRABLE_MISSING_KEYS`，
   而 `isDeferrableMissingSet` 是**全称**判定（`core:895-899`）⟹ 混进该键即整条在途推迟通道关闭
   —— **G3(b) 会把 G3(a) 自己拆掉**；
2. **空阻断**：`buildFeedbackText` 用 `.filter(Boolean)`（`judge:591-593`），表外的键**静默丢行**，
   用户看到一次 exit 2 + 通用指引 + 零具体原因；
3. **守卫方向反了**：`core.test:513-520` 是硬编码 enum → 抓「删文案」，抓不到「新键漏登记」。

**语料实证**：190 份 `specs/*/verification/verification-report.md` 中 **12 份**含 PENDING/待用户类标记，
真实形态是表格单元格（`| … | 待用户决策 | ⏸️ DEFERRED |`）、`⚠️ 待用户本地确认（…）`、
checkbox（`- [ ] **git fetch …**（待用户授权后执行）`）、加粗行、`🔴 MANUAL-PENDING — …`，
且**回填触发条件多半落在另一列或另一段**、中英混排带 emoji 前缀。
**这 12 份今天全部 PASS，按 FR-031 收紧后大概率翻成 block。**

**自相矛盾点（误伤面点破）**：FR-031 引入的正是 A-4 已证伪、K-7 裁决禁止的**文本启发式**
——只是把它从 transcript 挪到制品内容上。初稿同一张表里 G2 行写「禁止任何文本启发式」、
G3 行引入一个，**内部不自洽**。

**处置（已进设计）**：
- **FR-030 已 de facto 满足**：当前判据是 `exists && nonEmpty`（`core:1809-1810`），
  含 PENDING 的报告**本就通过**——「合规 PENDING 视为 verification-report.md 的合法形态」无需改代码；
- **FR-032 做**：判定器识别 PENDING 节并**落诊断码 + 未回填项计数**（**纯可观测性，不改判**）；
- **FR-031（裸 PENDING 按缺失）本卡显式裁剪**，理由三条：语料翻转风险（12/190）、
  与 K-7 裁决冲突（文本启发式）、安全收益近零（伪造成本 10 字）。
  再做的前置条件：先在这 190 份语料上跑判据 A/B 并公布翻转清单。
- **自愈路径靠成文**：把 F269「报告先落盘 + PENDING 标注 + 回填」写进 SKILL——
  长等待因此变成**合规态**，不必烧任何预算（与用户拍板的「不动预算」口径一致）。

### D-4 🔴 G2 的首次 Stop 处理改为 Design X（无历史指纹 ⟹ 走非计数路由）

**来源**：误伤面 C-1（初稿会让 GATE 暂停**多吃一次** exit 2：2 → 3；
且卡面验收量 `blockCount` 与真实伤害量「用户可见的 exit 2 次数」**方向相反**）。

初稿（Design Y：无历史指纹 ⟹ 走 `routeBlock`）逐轮：`exit2(b=1) → exit2(nb=1) → exit2(nb=2) → exit0`
= **3 次阻断**，比基线多一次，且 `blockCount` 增量 1 ≠ 卡面要求的 0。

**改为 Design X**（无历史指纹 ⟹ 视为「无进展」走非计数路由）：

| 场景 | 序列 | 对照基线 |
|---|---|---|
| 冻结暂停（GATE / 等后台 / 等外部） | `exit2(nb=1) → exit2(nb=2) → exit0(终态可见)` | **持平**（基线 2 次阻断），且 `blockCount` **零增量** ✅ |
| 有进展但不合规 | `exit2(nb=1) → 指纹变 exit2(b=1) → exit2(b=2) → exit0` | 多一次阻断（fail-closed 方向，给了多一次补救机会） |
| 最短完全绕过 | 仍是**吃 2 次 exit 2 后第 3 次放行** | **持平**，不更松 |

**放行地板不变**是采纳 Design X 的前提：两个同形桶阈值都是 2，交替投桶只会让被判方**多吃** exit 2。
⚠️ Design X **必须在第 2 轮对抗里由绕过面单独复审**（「首次即按无进展处理」是零成本自诱发的形态）。

### D-5 🔴 `routeNonBlock` 耗尽放行的**终态可见性必须 ≥ `releaseDegraded`**

**来源**：绕过面 C5。**主线程复核**：与「直接写 `blockCount:2`」相比**并非同价**——
旧路径留 `result:'failed'` + `degraded:true` 终态，新路径留 `result:'paused'` + `degraded:false`
（`judge:790-800`），与一次正常 GATE 暂停在审计流里近乎同形。
**F257 缺陷 2 的原文教训**（`judge:770` 注释自己引用的那条）就是
「两条放行路径可见性不对等，更安静那条成为首选绕过面」——G2 原样复发。

**处置**：`routeNonBlock` 耗尽放行 MUST 与 `releaseDegraded` **同档可见**
（终态 result 与 degraded 标注对齐、专属 trigger 码入闭集、loud stderr）；
且**指纹只可用于收紧**（指纹变化才允许重置计数），**不可用于放宽**。

### D-6 🔴 G4/G2 的跨组顺序是承重的，必须同批落地

**来源**：绕过面 C2。即使 G4 已按 D-2 降级为纯诊断码，
「先接线后重写返回契约」这一顺序风险仍适用于任何未来接入 `routeNonBlock` 的裁决类。

**处置**：`routeNonBlock` 的返回契约重写与**任何**接线 MUST 在同一提交；
先加一条端到端变异钉：**「非计数类裁决在计时器未耗尽时退出码必须为 2」**
（现状该契约只由注释守卫——F270 变异实验已证首行改 `return 0` 零端到端失败）。

### D-7 🔴 新增 **G0 前置**：judge 侧没有 canonical 诊断码表，R-12 护栏在本卡范围内**不成立**

**来源**：误伤面 W-5。**主线程复核**：成立且已实测。
`ledger-reader.test.mjs` 的派生守卫源是 `Object.values(LEDGER_DIAGNOSTICS)`，**只覆盖账本侧**；
judge 侧诊断码是散落字面量（`judge:246 / 531 / 693 / 783-784 / 975 / 1057 / 1060-1061 / 1135 / 1145`），
**没有 canonical 表** ⟹ 本卡新增的 `snapshot-stale` / 锁相关码 / GATE 指纹码**不会被任何守卫**抓到漏登记。

**处置**：新增 **G0** 为四组的前置：建 `JUDGE_DIAGNOSTICS` canonical 表、把既有散落码收进去、
守卫**从表派生**（与 `FOREIGN_DIALECT_DIAGNOSTICS` / `LEDGER_DIAGNOSTICS` 同源纪律），**再**加新码。

### D-8 🔴 G1 的陈旧锁判据不能只靠墙钟

**来源**：误伤面 W-4。**主线程复核**：与本仓 F273 已登记事实直接冲突——
宿主合盖睡眠导致**墙钟冻结约 5 分钟**。任何分钟级以下的 stale 超时都会在持锁进程**仍存活**时被接管，
**互斥被打破 = 比不加锁更坏**（两个写者都以为自己独占）。

**处置**：陈旧判据改 **pid 存活校验为主 + 墙钟兜底（≫ 重试上界，取 ≥60s）**；
接管事件本身**落码**（使「有人长期占锁」在审计流里可见）。
另：**撤回**初稿 B-9 里「`resetBlockState` 顺手删锁文件」的建议——
若锁被另一进程持有，删锁 = 主动破坏互斥，且 reset 在**合规**这条高频路径上（`judge:930-934`）。
改为：**reset 作为一次 mutation 走同一把锁**，锁文件**只由持有者 unlink**。

## 四、两路都**未能**证伪的点（站得住，不为凑数升格）

1. `prompt_id` / `background_tasks` / `stop_hook_active` / `last_assistant_message` 字段本身不可伪造（harness 进程写入）。
2. **不可擦 backstop 形态**（单调量直接比常量、不存锚）：`rm -rf` 状态目录无效，两路都没找到回退手法（已证伪路线 #22 的失效前提在此不成立）。
3. **同形桶之间 min 规则**：交替投桶只会让被判方**多吃** exit 2，无收益。
4. **账本并发追加安全**（B-8 的 O_APPEND 结论与 `lw` 实现一致）⟹ G1 把范围收窄到状态文件一处成立。
5. **锚点分量稳定**：`latestFixLineIndex` 只在 user 角色文本出现 fix 展开时变，`lineIndex` 是非空行序号、追加不改早前索引 ⟹ 冻结暂停期间不动。**R-5 复核成立**。
6. **子代理轮次不膨胀闸门三**：实测全库 **19108 条 assistant 条目中 `isSidechain===true` 为 0**——本 harness 子代理 transcript 独立成文件（审查者自己的怀疑被自己的数据推翻）。
7. **后台 Agent 只在派发时进账本一次**（`tool_response` 是 `async_launched` 派发回执），故「子代理自行完成导致指纹自发变化」构造不出来。
8. **20MB 超限不造成滑窗漂移**：超限直接 `transcript-too-large` fail-open 早退（`io:81-83`），无「读窗滑动 ⟹ 锚点漂移」形态。
9. **`verificationReport` 加 `content` 的传播面很小**：唯一判据在 `core:1809-1810`，`readArtifactFile` 无体积上限不截断，且不触碰见证侧只查 fix-report.md 的不对称 ⟹ **R-8 与普查硬约束 4 成立**。
10. **锁文件落点不入 US5 白名单**：`SPEC_DRIVER_PROJECT_MARKERS` 只看 `.specify/` 的**直接子项**，`.specify/runs/.fix-compliance-state/*.lock` 不命中 ⟹ **R-2 成立**（不会自举打开采集器闸门）。
11. **`releaseDegraded` 仍可达、无锁死组合**（F208 非 brick 保住）。
12. **G1 先于 G2 的排序**：按 B-7 更正后的方向（无界阻断、仅受 420 封顶）与 F208 冲突，排序理由站得住。
