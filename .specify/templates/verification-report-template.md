## Summary

### 交付判定合并律

> **本节把各层子检查的结论汇总为单一的交付结论。如实记录不等于判定不通过**——没有本节时，各层结论各自成立却无人把它们汇总成红灯。

**合并律**：任一子检查落在以下 **8 种态**中的任意一种时，交付整体判**不通过**——

1. 未实现　2. 未通过　3. 未执行（缺席）　4. 未对账　5. 报警未处置　6. 已违反　7. 未核验　8. 类别存疑

> 换算式：**8 = 原 7 态 + 1（`类别存疑`）**，单位：合并律态。

**兜底句**：**未被 `agents/verify.md`「既有取值 → 合并律态的显式映射表」映射的任何状态——既有的还是新增的——一律归入不通过侧**（默认严格）。**不得写成「新状态」**：各层子检查各有比合并律更早存在的取值词表（`COMPLIANT` / `PARTIAL` / `EVIDENCE_MISSING` / `RESIDUAL_FOUND` / `DOC_DRIFT` / `PASS` / `FAIL` / `SKIPPED` / `UNKNOWN`），「新」字会把它们整类排除在兜底之外。
